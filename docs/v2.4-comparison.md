# SFG OMR LAB v2.4 — Universal Comparison Lab

## Usage
Open `/#/compare` on GitHub Pages. Upload **one photo** and select the engines to run. Every selected engine runs sequentially even if the primary OpenCV scanner passes. Click **Corner overlay** to compare page predictions on the original image, and **Diagnostics** to export Compact, Differences or Full reports. No uploads of photo data to a backend are performed.

## Supported engines
| Engine | Scope | Deployment |
| --- | --- | --- |
| v2.4.0 | Full scanner with cautious QR-less provisional extraction | Current site; isolated iframe |
| v2.3.45 | Archived full optical scanner | `/v2.3.45/`; same-origin isolated iframe |
| v2.2.6 Lite | Historical full optical scanner | `/versions/v2.2.6/`; isolated iframe |

| Scanic DocCornerNet | Document corner detection only | Pinned 1.8.0, WASM and .ort self-hosted |
| DocAligner LCNet-100 | Document corner detection only | Pinned Quadscan 1.0.0, ONNX |
| DocAligner FastViT-T8 | Document corner detection only | Pinned Quadscan 1.0.0, 13MB ONNX |
| SmallOMRNet | **Experimental** filled/empty bubble-crop classification only | 64×64 grayscale ONNX, 200 crops, AGPL-3.0 |

The last engine requires a perspective-corrected page from the current scanner. It is independently compared with, but never used to overwrite, the optical classifications. It was trained on synthetic checkbox crops and is **not calibrated for the SFG circular bubble sheet**. There is no proof it generalizes to erasures/crosses. It is an experimental diagnostic, not a grade. The model itself is licensed AGPL-3.0; the model license and attribution notice are published alongside its weights. The host app's other source licensing remains separate, subject to applicable license obligations.

## Reproducible geometry work
The overlay shows predicted four-point page boundaries on the original photo, not printed marker centers. Click **Mark reference corners**, then select the **actual paper boundary** in **TL, TR, BR, BL** order. Only confirm it after checking visually. The report computes mean pixel distance per model to the confirmed reference.

The image hash and engine version are included in exported files. This is an annotation/evidence pipeline, **not browser retraining**. Improve conventional OpenCV by inspecting persistent errors across many representative manually verified images, then add regression tests to the repository.

## Compact diagnostic guidelines
- Always include image SHA-256, engine IDs/versions, status, execution time, verification status and critical errors.
- Distinguish a model that suggests corners from a complete scanner that independently verifies identity/timing and reads bubbles.
- For QR-less extraction, label results provisional and prohibit automatic scoring.
- Include the 50-question answer map **only** when that engine actually analyzed all 50 questions.
- Report disagreements only between comparable fully run scanner engines; bubble-model measurements are exploratory and separate.
- Full JSON contains per-engine logs and bubble measurements. Do **not** embed the image/photograph in the diagnostic JSON.

## Architecture and constraints
The host comparison page uses a browser-only, same-origin postMessage bridge running in separate iframes for historical scanner generations. Every message validates both the origin and request ID; a historical engine gets only the selected File data, returns its scan result, then its iframe is removed. AI detectors use lazy self-hosted models. The host runs engines sequentially and an engine failure does not stop others. Per-engine timeout is 120 seconds. Files are capped at 25MB.

GitHub Pages hosts the compiled JS, archived scanner bundles, wasm and model assets. It **does not execute scans on a backend**. An internet connection is still required to initially load the site and assets; the current historical scanner HTML also fetches OpenCV.js from docs.opencv.org, so complete disconnected/offline first-load operation is not provided.

## Important limitations
1. **Same-image inputs do not imply same interpretations.** Historical scanning thresholds and validators differ; preserve each build's original behavior in results.
2. **Model confidence is not accuracy.** SmallOMRNet uses unvalidated/candidate scores; page detectors must be checked against human-verified corners and printed landmarks.
3. **No scoring during comparison.** The comparison UI never submits answers to a practice test. Official scoring remains confined to the main scanner's verified workflow.
4. **No automatic learning/training.** Manual annotations and reports are exported so algorithms can be improved and retested.
5. **Privacy:** The source image remains in the browser. Third-party code and weights are served as static assets; no image-processing API is called. OpenCV is loaded from its external CDN in historical builds.
6. **Runtime validation:** GitHub Actions tests TypeScript, lint, scanner regressions, main Vite build, historic Vite builds, and presence of all model assets. Accuracy must still be validated using genuine photos after deployment.

## Failure investigation
If a historical engine times out, inspect the corresponding error row; the rest should continue. If SmallOMRNet fails, confirm the current scanner returned a perspective-corrected page and the AGPL model weight and ORT WASM assets are accessible. If AI corners are plausible but verification fails, do not loosen QR/timing gates in automatic scoring. Mark actual reference corners and inspect pixel-level discrepancies.
